# ANALYSIS-002: Plan/Session Note Render Architecture

## Overview

This analysis captures a substantial architectural exploration of the planning skill's plan-note and session-note infrastructure. The exploration was triggered by structural drift observed in PLAN-001-skills-ecosystem (large H4 subsection placeholders left in DONE parts; basic-memory replace_section silently appending H2 duplicates at the file bottom; 30+ sequential edit_note calls per state-propagation cycle; Mermaid graph styling falling out of sync with substatus changes). The conclusion: the planning skill's read/write loop should adopt the same architectural pattern as the composition library itself — LLM authors intent and content; a deterministic Bun + TS render script applies state and content to produce canonical markdown.

The analysis surfaces 11 locked decisions (D-1..D-11) plus full template specifications, full Zod schema drafts, full parser drafts, mutation API sketches, monorepo restructure proposal, and a migration / dogfooding plan. All decisions are LOCKED pending formal ADR-003 authorship + brain:---adr-review cycle in a future session. SPEC-007 (Plan/Session Render Implementation) is the implementation target.

## Problem framing

The trigger was structural drift in PLAN-001-skills-ecosystem observed after the /end pipeline closed SESSION-2026-05-19_01. Per-part H4 subsections (Tasks, Intra-part Deps Graph, Editor Mirror IDs, Pending User Decisions) across all 6 spec.SPEC-NNN parts retained placeholder text despite the parent parts being marked DONE. Drift remediation required about 40 edit operations + a comprehensive PLAN walk-through, captured in commit f280c0f.

Specific drift surfaces identified during remediation:

1. basic-memory edit_note replace_section operation silently appended new H2 sections at the bottom of the file when targeting H4 subsections, creating a ~210-line duplicate block instead of replacing the H4 content in place. Confirmed via Brain MCP read_note that the in-memory model also reflected the duplicates (not a markdown-vs-database divergence — the operation genuinely created bottom-appended H2s).

2. State propagation required 30+ sequential edit_note calls per major event (set-part-done, Mermaid update, Progress Dashboard rollup, Phase Progression flip, DoD checkbox flips, Decision Log append, Progress Log append, cross-part dep graph edge update). Each call triggered basic-memory parse + render. Cumulative time per propagation: 1-3 minutes.

3. Mermaid graph styling drifted: nodes had pending class when their substatus was DONE; edge linkStyle indices misaligned after subgraph changes; classDef palette inconsistencies between deps graphs in different parts. Manual reconciliation required matching the styling template across 10+ Mermaid blocks per PLAN.

4. find_replace anchoring required complex multi-line context with embedded special characters (arrows, backticks, double-brackets, emoji checkmarks) where any single character drift broke the replacement.

5. The basic-memory bullet parser treats any bullet containing double-bracket wikilink syntax as a malformed typed-relation candidate, failing validation. Workaround: rephrase prose bullets to plain-text title references; reserve wikilinks for the Relations section.

6. Permalink dash-one suffix collisions after delete+recreate or write_note+move_note sequences accumulated to about 95 unresolved across 6 SPEC subtrees.

User's framing of the corrected responsibility split, captured verbatim:

> Relationship to plan notes: The plan note holds a workflow's authoritative progress state and is mutated in place as steps advance. The session note is the append-only event log produced during a plan step's execution. A plan transition (ready to in progress) initiates the work that a session captures; on completion, the plan transitions again (in progress to done) and references the session note as the receipt for that step. Plans look forward; sessions look backward; together they form the workflow's read/write loop.

This framing is the foundational invariant for everything below.

## Responsibility audit

Every current PLAN section was classified by nature (state vs event vs documentation) and assigned to a destination.

### PLAN keeps (forward-looking workflow state)

- Frontmatter (title, type=plan, status, complexity_tier, branches, permalink, tags)
- Scope (workflow intent prose)
- Objectives (checklist with per-item done state)
- Progress Dashboard (derived rollup of parts substatus by phase; regenerated by render script)
- Cross-Part Dependency Graph (derived Mermaid from parts depends_on + phase grouping; regenerated by render script)
- Per-part state: Substatus, Owning session, Completing session, Outcome, Source artifacts, Depends on, DoD
- Per-part D-N substatus list (decisions parts only; slim format — D-N id + LOCKED + one-line topic; verbose content lives in the ADR)
- Tasks (Active / Backlog / Archive three-table split, consolidated at PLAN top level with a Part column)
- Pending User Decisions (consolidated at PLAN top level)
- Editor Mirror IDs (consolidated at PLAN top level; persistent T-ID to CC-ID to Cursor-ID map)
- Blockers (forward-looking list)
- Observations and Relations (CONVENTIONS Section 4.0 invariant final two sections)

### PLAN drops (moved out)

- Workflow Plan top-level prose: skill protocol documentation, not workflow state — moves to skill spec
- Decision Log top-level: event-shaped (chronological log of decision lock events) — moves to SESSION events
- Progress Log top-level: event-shaped (duplicates SESSION Event NN entries) — moves to SESSION events
- Per-part Workflow Plan prose: skill protocol documentation — moves to skill spec
- Per-part Tasks tables: duplicate headers + structure across N parts — consolidated into top-level Tasks with a Part column
- Per-part Intra-part Deps Graph: redundant — Cross-Part Deps Graph + depends_on already establishes order — dropped entirely
- Per-part Editor Mirror IDs: per-part scoping was duplication — consolidated at PLAN top level
- Per-part Pending User Decisions: per-part scoping was duplication — consolidated at PLAN top level

### SESSION keeps (backward-looking event ledger)

- Frontmatter (title, type=session, status, binds_to, permalink, tags)
- Scope (session intent prose)
- Bound PLAN pointer list with worked_parts
- Event NN entries (append-only); each event has typed-field bullets (Type, Part, Transition, Outcome, Decision IDs, Task, Agent, Verdict, Tally) followed by free-text body
- Observations and Relations

### SESSION drops (proposed and rejected)

An earlier proposal moved Tasks tables and per-session Pending User Decisions and Editor Mirror IDs into the SESSION note. This was rejected by the user with the observation that tasks are state with a status state machine; the events that transition them belong in SESSION (referencing the task by ID), but the tasks themselves live in PLAN. Same pattern applies to Pending User Decisions and Editor Mirror IDs: persistent state in PLAN; events that surface or resolve them in SESSION.

### Root cause of original bloat

Two compounding sources, neither of which was "Tasks shouldn't be in PLAN":

1. Per-part duplication. The same Tasks/Editor/Pending headers were repeated × 10 parts. Same column structure; different rows. Consolidation at PLAN top level (with a Part column) eliminates the duplication while preserving the data.

2. Event commentary embedded in task rows. The Resolved column carried prose like "PASS unanimous; no P1; 134K tokens" — that's event detail, not task state. The task row should reference the resolving event by id; the event body carries the detail.

Net effect of the fix: about 70% bulk reduction in PLAN markdown; SESSION grows by 30-50 lines per session (consolidated Tasks references) but stays genuinely session-scoped.

## Architecture decisions D-1..D-11 (LOCKED pending ADR-003 formalization)

### D-1: Markdown is authoritative state

Decision: The markdown files in docs/** are the single source of truth for plan and session state. No parallel state.yaml as a second source of truth.

Rationale: basic-memory's binary rule (CONVENTIONS Section 1.7.1) already establishes markdown as canonical for Brain notes. The markdown files are what gets committed to git, indexed by basic-memory, and surfaced to readers. Introducing a state.yaml as authoritative would create a dual-truth problem: if the .md and the .yaml ever diverge, which wins? The drift problem we are trying to solve would reappear one layer down.

Alternative considered: state.yaml as authoritative + .md regenerated from it on every state change. This was the initial proposal in the exploration. The author of the alternative (orchestrator) was corrected by the user; the corrected pattern is the locked one above.

Status: LOCKED.

### D-2: PLAN owns forward state; SESSION owns backward events

Decision: PLAN tracks all forward-looking workflow state (parts, tasks, pending decisions, editor mirror IDs, dashboard rollups, deps graph). SESSION is a pure append-only event ledger that captures what happened during a session, referencing PLAN state by id where relevant.

Rationale: Per the user's read/write loop framing — plans look forward (mutated in place as steps advance); sessions look backward (capture events produced during a plan step's execution). A plan transition initiates work that a session captures; on completion, the plan transitions again and references the session as the receipt.

Alternative considered: putting Tasks in SESSION (initial responsibility audit). Rejected because tasks ARE state with a status state machine (PENDING to IN_PROGRESS to DONE), not events. The transitions are events; the tasks themselves are state.

Status: LOCKED.

### D-3: Deterministic render scripts replace LLM-authored find_replace cycles

Decision: Plan and session note mutations go through Bun + TypeScript scripts that parse markdown into a typed in-memory model, apply typed mutations, re-emit the entire document deterministically, validate against the Zod schema, and write atomically. The LLM provides intent (which mutation, with what parameters) and any dynamic prose content; the script applies state and content to produce canonical markdown.

Rationale: LLM-authored find_replace / edit_note cycles produce drift through multiple failure modes: basic-memory replace_section silently appending H2 sections at the bottom; 30+ sequential edits per state propagation each triggering basic-memory parse+render; Mermaid graph styling falling out of sync with substatus; find_replace anchoring brittleness on multi-line context with special characters. A deterministic script with full-document propagation eliminates each of these. The architectural pattern is the same as the composition library's: LLM plans, script executes mechanically with cryptographic invariants.

Alternative considered: keep LLM-authored edit_note but write better prompts + more careful anchoring. Rejected because the failure modes are inherent to incremental editing without full-document state-then-render propagation.

Status: LOCKED.

### D-4: Zod schema as validation contract

Decision: Plan and session note structures are validated by Zod schemas living in _shared/composition/src/schemas/ (plan-note.ts, session-note.ts, common.ts). Schema runs on every parse and pre-write. Validation includes cross-field invariants (DONE part must have outcome; task.part must reference a valid part; event numbers must be continuous starting at 1).

Rationale: Type safety + runtime validation + cross-field invariants caught at a known boundary. Mirrors ADR-001 D-1 (Zod for plan validation). The schema is the contract between LLM authoring layer and the deterministic render script.

Alternative considered: JSON Schema. Rejected per ADR-001 D-1 reasoning (Zod is TS-native, single source of truth between types and validation).

Status: LOCKED.

### D-5: T-NN tasks are plan-scoped (not session-scoped)

Decision: Task IDs use the format T-NN where NN is a plan-global counter (2+ digits), continuous across sessions of the same workflow. Previously T-NN was session-scoped per the existing feedback_session_protocol guidance.

Rationale: Tasks are state living in PLAN; therefore their identifiers span the PLAN lifecycle, not the session lifecycle. Continuous numbering across sessions makes cross-session task references unambiguous.

Alternative considered: keep T-NN session-scoped + prefix with session id for plan-level references. Rejected because the cross-session reference is more cumbersome.

Status: LOCKED. Migration: existing T-IDs in PLAN-001 are already plan-global continuous (T-01..T-57 across the bootstrap session); no renumbering needed.

### D-6: Tasks consolidated at PLAN top level with three-table split

Decision: A single Tasks section at PLAN top level contains three sub-tables: Active (IN_PROGRESS tasks), Backlog (PENDING tasks), Archive (DONE tasks, optionally inside a details collapse). The tasks table schema has columns: T-ID, Subject, Part, Agent, Effort, Status, Created (event ref), Resolved (event ref). The per-part Tasks H4 sections are dropped entirely.

Rationale: Per-part Tasks duplication was the primary bloat source. Consolidation matches the existing feedback_session_protocol three-table hybrid pattern, just relocated from SESSION to PLAN where state belongs. The Active/Backlog/Archive split keeps the visible PLAN size manageable even when the workflow has 100+ tasks.

Status: LOCKED.

### D-7: Mermaid as separate render concern

Decision: The Mermaid rendering logic for the Cross-Part Dependency Graph is a separate pure function renderMermaid(parts, layout) callable independently. Single source of truth for graph styling. Used internally by applyPlanMutation (auto-propagate on every substatus change) and exposed as a standalone command for manual regeneration when drift is detected.

Rationale: Mermaid charts were a particularly painful drift surface — class assignments, substatus icons, and edge linkStyle indices all needed consistent updates that LLM-authored edit_note couldn't reliably coordinate.

Status: LOCKED.

### D-8: Round-trip property test as gate

Decision: render(parse(md)) === md (SHA-256 char-identity, modulo intentional template normalization) is a CI gate for the plan/session render pipeline. PLAN-001 itself becomes the first round-trip fixture.

Rationale: Same hash-validation principle as the composition library's adapter contract per ADR-001 F-8. Drift becomes mathematically impossible inside the structural portion of any rendered plan/session note.

Status: LOCKED.

### D-9: PUD + Editor Mirror IDs at PLAN top level (state, not event)

Decision: Pending User Decisions and Editor Mirror IDs are top-level PLAN sections (not per-part, not in SESSION). PUDs are open AskUserQuestion prompts that span sessions until resolved; Editor Mirror IDs are the persistent T-ID to CC-ID to Cursor-ID mapping.

Rationale: These are state, not events. Per-part scoping was duplication; SESSION scoping conflated state with events.

Status: LOCKED.

### D-10: No Decision Log / Progress Log in PLAN

Decision: PLAN drops the top-level Decision Log and Progress Log sections. Their content was event-shaped and duplicated SESSION Event NN entries. If a cross-session executive summary is wanted later, build a separate "bun run plan:history PLAN-NNN" command that pretty-prints from session events rather than embedding the rollup in the artifact.

Rationale: Decision-lock events and progress events are SESSION-scoped event-log content. Removing them is the largest single source of PLAN bloat reduction.

Status: LOCKED.

### D-11: Workflow Plan prose moves to skill docs

Decision: PLAN drops the top-level Workflow Plan prose and per-part Workflow Plan prose. These described HOW work gets executed (the skill protocol). That content belongs in the skill spec, not in workflow state.

Rationale: Skill protocol documentation is invariant across plan instances. It should live once in the skill's SKILL.md (or reference files), not be re-authored into every plan note.

Status: LOCKED.

```ts
  }
```

### Schema design decisions baked in

1. Strict objects throughout (.strict()) — unknown fields fail validation. Schema is single source of truth for shape.
2. Discriminated union for events — every event has a type field; event-type-specific fields are statically typed.
3. Cross-field invariants in superRefine — task → part, depends_on → part, status consistency, event-number continuity, first-event-is-session-start.
4. outcome required when substatus is DONE; resolved_at_event required when status is DONE.
5. branches[] on PLAN, binds_to[] on SESSION — arrays for the many-to-many case. Min 1.
6. No per-part objectives — objectives are workflow-level only.
7. tasks, pending_decisions, editor_mirror default to [] — empty arrays for plans that haven't accrued any yet.
8. PUD options 2-4 — matches AskUserQuestion's option constraint per the ask protocol.
9. No decision_log / progress_log arrays — absence enforces the responsibility split.
10. Observation min 3, Relations min 2 — matches CONVENTIONS Section 6.

```ts
import yaml from 'js-yaml';
import { toString as nodeToString } from 'mdast-util-to-string';
import type { Root, Heading, Paragraph, List, ListItem, Table, Yaml } from 'mdast';

export type Section = {
  heading: string;
  depth: 2;
  children: Root['children'];
};

export type SubSection = {
  heading: string;
  depth: 3;
  children: Root['children'];
};

export function extractFrontmatter(tree: Root): Record<string, unknown> {
  const yamlNode = tree.children.find((c): c is Yaml => c.type === 'yaml');
  if (!yamlNode) throw new ParseError('frontmatter missing', { path: ['frontmatter'] });
  const parsed = yaml.load(yamlNode.value);
  if (parsed == null || typeof parsed !== 'object') {
    throw new ParseError('frontmatter is not a YAML mapping', { path: ['frontmatter'] });
  }
  return parsed as Record<string, unknown>;
}

export function sectionizeH2(tree: Root): Map<string, Section> {
  const sections = new Map<string, Section>();
  let current: Section | null = null;
  for (const node of tree.children) {
    if (node.type === 'heading' && node.depth === 2) {
      if (current) sections.set(current.heading, current);
      current = { heading: nodeToString(node), depth: 2, children: [] };
    } else if (current) {
      current.children.push(node);
    }
  }
  if (current) sections.set(current.heading, current);
  return sections;
}

export function sectionizeH3(children: Root['children']): Map<string, SubSection> {
  const sections = new Map<string, SubSection>();
  let current: SubSection | null = null;
  for (const node of children) {
    if (node.type === 'heading' && node.depth === 3) {
      if (current) sections.set(current.heading, current);
      current = { heading: nodeToString(node), depth: 3, children: [] };
    } else if (current) {
      current.children.push(node);
    }
  }
  if (current) sections.set(current.heading, current);
  return sections;
}

export function proseFromChildren(children: Root['children']): string {
  return children
    .filter((c) => c.type === 'paragraph')
    .map((c) => nodeToString(c))
    .join('\n\n')
    .trim();
}

const WIKILINK_RE = /^\[\[(.+?)\]\]$/;

export function stripWikilink(text: string): { ref: string } | string {
  const trimmed = text.trim();
  const m = trimmed.match(WIKILINK_RE);
  return m ? { ref: m[1] } : trimmed;
}

export function findList(children: Root['children']): List | null {
  return children.find((c): c is List => c.type === 'list') ?? null;
}

export function findTable(children: Root['children']): Table | null {
  return children.find((c): c is Table => c.type === 'table') ?? null;
}

export function tableRows(table: Table): string[][] {
  const [, ...bodyRows] = table.children;
  return bodyRows.map((row) =>
    row.children.map((cell) => nodeToString(cell).trim())
  );
}

export function tableHeader(table: Table): string[] {
  const headerRow = table.children[0];
  return headerRow.children.map((cell) => nodeToString(cell).trim());
}

// Parses "- **Field**: value" or "- Field: value" bullet patterns into a key-value map.
const FIELD_BULLET_RE = /^\*\*?(.+?)\*?\*:\s*(.*)$/s;

export function bulletFieldMap(list: List | null): Map<string, string> {
  const out = new Map<string, string>();
  if (!list) return out;
  for (const item of list.children) {
    const text = nodeToString(item).trim();
    const m = text.match(FIELD_BULLET_RE);
    if (m) out.set(m[1].trim(), m[2].trim());
  }
  return out;
}

export function checkboxItems(list: List | null): Array<{ text: string; done: boolean }> {
  if (!list) return [];
  return list.children.map((item: ListItem) => ({
    text: nodeToString(item).trim(),
    done: item.checked === true,
  }));
}

export class ParseError extends Error {
  constructor(message: string, public meta: { path: string[]; context?: unknown }) {
    super(`[parser] ${message} at ${meta.path.join('.')}`);
  }
}
```

### parsers/plan-note.ts

```ts
import { unified } from 'unified';
import remarkParse from 'remark-parse';
import remarkFrontmatter from 'remark-frontmatter';
import { toString as nodeToString } from 'mdast-util-to-string';
import type { Root } from 'mdast';

import { PlanNoteSchema, type PlanNote } from '../schemas/plan-note';
import {
  extractFrontmatter, sectionizeH2, sectionizeH3, proseFromChildren,
  findList, findTable, tableRows, tableHeader, bulletFieldMap, checkboxItems,
  stripWikilink, ParseError,
} from './ast-helpers';

export function parsePlanNote(markdown: string): PlanNote {
  const tree = unified()
    .use(remarkParse)
    .use(remarkFrontmatter, ['yaml'])
    .parse(markdown) as Root;

  const frontmatter = extractFrontmatter(tree);
  const h2 = sectionizeH2(tree);

  const scopeSection = h2.get('Scope');
  if (!scopeSection) throw new ParseError('Scope section missing', { path: ['scope'] });
  const { scope, source_reference } = parseScope(scopeSection.children);

  const objectives = parseObjectives(h2.get('Objectives')?.children ?? []);
  const parts = parsePartsSection(h2.get('Parts')?.children ?? []);
  const tasks = parseTasksSection(h2.get('Tasks')?.children ?? []);
  const pending_decisions = parsePendingDecisions(h2.get('Pending User Decisions')?.children ?? []);
  const editor_mirror = parseEditorMirror(h2.get('Editor Mirror IDs')?.children ?? []);
  const blockers = parseBlockers(h2.get('Blockers')?.children ?? []);
  const observations = parseObservations(h2.get('Observations')?.children ?? []);
  const relations = parseRelations(h2.get('Relations')?.children ?? []);

  return PlanNoteSchema.parse({
    frontmatter,
    scope,
    source_reference,
    objectives,
    parts,
    tasks,
    pending_decisions,
    editor_mirror,
    blockers,
    observations,
    relations,
  });
}

function parseScope(children: Root['children']): { scope: string; source_reference?: string } {
  let scopeParas: string[] = [];
  let source_reference: string | undefined;
  for (const node of children) {
    if (node.type !== 'paragraph') continue;
    const text = nodeToString(node).trim();
    const sourceMatch = text.match(/^\*\*Source\*\*:\s*(.+)$/s);
    if (sourceMatch) {
      source_reference = sourceMatch[1].trim().replace(/^`|`$/g, '');
    } else {
      scopeParas.push(text);
    }
  }
  return { scope: scopeParas.join('\n\n'), source_reference };
}

function parseObjectives(children: Root['children']): PlanNote['objectives'] {
  const list = findList(children);
  const items = checkboxItems(list);
  return items.map((it, i) => ({ id: `obj-${i + 1}`, text: it.text, done: it.done }));
}

function parsePartsSection(children: Root['children']): PlanNote['parts'] {
  const h3 = sectionizeH3(children);
  return Array.from(h3.entries()).map(([heading, sub]) => parsePart(heading, sub.children));
}

const PART_HEADING_RE = /^(\S+)\s+—\s+(.+)$/;

function parsePart(heading: string, children: Root['children']): PlanNote['parts'][number] {
  const m = heading.match(PART_HEADING_RE);
  if (!m) throw new ParseError(`Part heading invalid: ${heading}`, { path: ['parts'] });
  const [, id, title] = m;

  const attrList = findList(children);
  const attrs = bulletFieldMap(attrList);

  const substatus = attrs.get('Substatus');
  if (!substatus) throw new ParseError(`Part ${id} missing Substatus`, { path: ['parts', id] });

  const owning_session_raw = attrs.get('Owning session');
  const completing_session_raw = attrs.get('Completing session');
  const outcome_raw = attrs.get('Outcome');
  const source_artifacts_raw = attrs.get('Source artifacts') ?? '';
  const depends_on_raw = attrs.get('Depends on') ?? '';

  const dod = parseDodFromPart(children);
  const decisions = parseDecisionsTable(children);
  const phase = derivePhaseFromId(id);

  return {
    id,
    phase,
    title,
    substatus: substatus as any,
    owning_session: owning_session_raw ? stripWikilinkToSessionId(owning_session_raw) : undefined,
    completing_session: completing_session_raw ? stripWikilinkToSessionId(completing_session_raw) : undefined,
    outcome: outcome_raw ? parseOutcome(outcome_raw) : undefined,
    source_artifacts: parseSourceArtifacts(source_artifacts_raw),
    depends_on: parseDependsOn(depends_on_raw),
    dod,
    decisions,
  };
}

function derivePhaseFromId(id: string): PlanNote['parts'][number]['phase'] {
  if (id === 'research') return 'research';
  if (id.startsWith('decisions.')) return 'decisions';
  if (id === 'spec-decomposition') return 'spec-decomposition';
  if (id.startsWith('spec.')) return 'spec';
  if (id.startsWith('build.')) return 'build';
  if (id === 'review') return 'review';
  if (id === 'end') return 'end';
  throw new ParseError(`Cannot derive phase from part id: ${id}`, { path: ['parts', id] });
}

function parseDodFromPart(children: Root['children']): PlanNote['parts'][number]['dod'] {
  for (let i = 0; i < children.length; i++) {
    const node = children[i];
    if (node.type === 'paragraph' && nodeToString(node).trim().startsWith('**Definition of Done**')) {
      for (let j = i + 1; j < children.length; j++) {
        if (children[j].type === 'list') return checkboxItems(children[j] as any);
        if (children[j].type === 'heading') break;
      }
    }
  }
  return [];
}

function parseDecisionsTable(children: Root['children']): PlanNote['parts'][number]['decisions'] {
  for (let i = 0; i < children.length; i++) {
    const node = children[i];
    if (node.type === 'paragraph' && nodeToString(node).trim().startsWith('**Locked decisions**')) {
      for (let j = i + 1; j < children.length; j++) {
        const next = children[j];
        if (next.type === 'table') {
          return tableRows(next).map((row) => ({ id: row[0], status: row[1] as any, topic: row[2] }));
        }
        if (next.type === 'heading') break;
      }
    }
  }
  return undefined;
}

function stripWikilinkToSessionId(text: string): string {
  const stripped = stripWikilink(text);
  if (typeof stripped === 'string') return stripped;
  const m = stripped.ref.match(/^(SESSION-\d{4}-\d{2}-\d{2}_\d{2}):/);
  if (!m) throw new ParseError(`Session wikilink invalid: ${stripped.ref}`, { path: ['session-ref'] });
  return m[1];
}

function parseOutcome(text: string): { kind: 'file' | 'wikilink'; ref: string } {
  const stripped = stripWikilink(text);
  if (typeof stripped === 'object') return { kind: 'wikilink', ref: stripped.ref };
  return { kind: 'file', ref: text.replace(/^`|`.*$/g, '').replace(/`/g, '') };
}

function parseSourceArtifacts(text: string): Array<{ ref: string } | string> {
  if (!text) return [];
  return text.split(/[,;]/).map((s) => stripWikilink(s.trim())).filter(Boolean);
}

function parseDependsOn(text: string): string[] {
  if (!text || text === '(none)') return [];
  return text.split(/[,;]/).map((s) => s.trim()).filter(Boolean);
}

function parseTasksSection(children: Root['children']): PlanNote['tasks'] {
  const h3 = sectionizeH3(children);
  const tasks: PlanNote['tasks'] = [];
  for (const [subHeading, sub] of h3.entries()) {
    const table = findTable(sub.children);
    if (!table) continue;
    const header = tableHeader(table);
    const rows = tableRows(table);
    const idx = (col: string) => header.findIndex((h) => h.toLowerCase() === col.toLowerCase());
    for (const row of rows) {
      tasks.push({
        id: row[idx('T-ID')] || row[0],
        subject: row[idx('Subject')],
        part: row[idx('Part')] || '',
        agent: row[idx('Agent')],
        files: [],
        effort: row[idx('Effort')] as any,
        status: (row[idx('Status')] as any) ?? subHeadingToStatus(subHeading),
        created_at_event: parseEventRef(row[idx('Created')]),
        resolved_at_event: parseEventRef(row[idx('Resolved')]),
      });
    }
  }
  return tasks;
}

function subHeadingToStatus(h: string): 'IN_PROGRESS' | 'PENDING' | 'DONE' {
  if (h === 'Active') return 'IN_PROGRESS';
  if (h === 'Backlog') return 'PENDING';
  return 'DONE';
}

function parseEventRef(text: string | undefined): number | undefined {
  if (!text) return undefined;
  const m = text.match(/^E(\d+)$/);
  return m ? Number(m[1]) : undefined;
}

function parsePendingDecisions(children: Root['children']): PlanNote['pending_decisions'] {
  const text = proseFromChildren(children);
  if (text.startsWith('None')) return [];
  return [];
}

function parseEditorMirror(children: Root['children']): PlanNote['editor_mirror'] {
  const table = findTable(children);
  if (!table) return [];
  const header = tableHeader(table);
  const idx = (col: string) => header.findIndex((h) => h.toLowerCase().includes(col.toLowerCase()));
  return tableRows(table).map((row) => ({
    task_id: row[idx('T-ID')],
    cc_id: row[idx('CC-ID')] && row[idx('CC-ID')] !== '—' ? row[idx('CC-ID')] : null,
    cursor_id: row[idx('Cursor')] && row[idx('Cursor')] !== '—' ? row[idx('Cursor')] : null,
    last_synced: row[idx('Last synced')] && row[idx('Last synced')] !== '—' ? row[idx('Last synced')] : null,
  }));
}

function parseBlockers(children: Root['children']): string[] {
  const text = proseFromChildren(children);
  if (text.startsWith('None')) return [];
  const list = findList(children);
  if (!list) return text ? [text] : [];
  return list.children.map((item) => nodeToString(item).trim());
}

function parseObservations(children: Root['children']): PlanNote['observations'] {
  const list = findList(children);
  if (!list) return [];
  return list.children.map((item) => {
    const text = nodeToString(item).trim();
    const m = text.match(/^\[(\w+)\]\s+(.+?)(\s+(#[a-z0-9-]+(\s+#[a-z0-9-]+){0,2}))?$/);
    if (!m) throw new ParseError(`Observation malformed: ${text}`, { path: ['observations'] });
    const tags = (m[4] ?? '').split(/\s+/).filter(Boolean).map((t) => t.slice(1));
    return { category: m[1] as any, text: m[2].trim(), tags };
  });
}

function parseRelations(children: Root['children']): PlanNote['relations'] {
  const list = findList(children);
  if (!list) return [];
  return list.children.map((item) => {
    const text = nodeToString(item).trim();
    const m = text.match(/^(\w+)\s+\[\[(.+?)\]\]$/);
    if (!m) throw new ParseError(`Relation malformed: ${text}`, { path: ['relations'] });
    return { verb: m[1] as any, target: m[2] };
  });
}
```

```ts
} from './ast-helpers';

export function parseSessionNote(markdown: string): SessionNote {
  const tree = unified().use(remarkParse).use(remarkFrontmatter, ['yaml']).parse(markdown) as Root;

  const frontmatter = extractFrontmatter(tree);
  const h2 = sectionizeH2(tree);

  const scope = proseFromChildren(h2.get('Scope')?.children ?? []);
  const bound_plans = parseBoundPlans(h2.get('Bound PLAN')?.children ?? h2.get('Bound PLANs')?.children ?? []);
  const events = parseEvents(h2.get('Events')?.children ?? []);
  const observations = parseObservations(h2.get('Observations')?.children ?? []);
  const relations = parseRelations(h2.get('Relations')?.children ?? []);

  return SessionNoteSchema.parse({
    frontmatter,
    scope,
    bound_plans,
    events,
    observations,
    relations,
  });
}

function parseBoundPlans(children: Root['children']): SessionNote['bound_plans'] {
  const list = findList(children);
  if (!list) return [];
  return list.children.map((item) => {
    const text = nodeToString(item).trim();
    const m = text.match(/^\[\[(.+?)\]\]\s+—\s+worked parts:\s*(.+)$/);
    if (!m) throw new ParseError(`Bound PLAN ref malformed: ${text}`, { path: ['bound_plans'] });
    return {
      ref: m[1],
      worked_parts: m[2].split(/[,;]/).map((s) => s.trim()).filter(Boolean),
    };
  });
}

const EVENT_HEADING_RE = /^Event\s+(\d+)\s+—\s+(.+)$/;

function parseEvents(children: Root['children']): Event[] {
  const h3 = sectionizeH3(children);
  return Array.from(h3.entries()).map(([heading, sub]) => {
    const m = heading.match(EVENT_HEADING_RE);
    if (!m) throw new ParseError(`Event heading invalid: ${heading}`, { path: ['events'] });
    const n = Number(m[1]);
    const title = m[2];

    const fieldList = findList(sub.children);
    const fields = bulletFieldMap(fieldList);

    const body = proseFromChildren(sub.children.filter((c) => c.type === 'paragraph'));

    const type = fields.get('Type') ?? 'state-change';
    const eventRaw: Record<string, unknown> = { n, title, body, type };

    for (const [k, v] of fields.entries()) {
      switch (k) {
        case 'Part': eventRaw.part = v; break;
        case 'Type': break;
        case 'Transition': {
          const [from, to] = v.split('→').map((s) => s.trim());
          eventRaw.from = from;
          eventRaw.to = to;
          break;
        }
        case 'Outcome': eventRaw.outcome = parseOutcomeRef(v); break;
        case 'Decision IDs': eventRaw.decision_ids = v.split(/[,;]/).map((s) => s.trim()); break;
        case 'Task': eventRaw.task = v; break;
        case 'Agent': eventRaw.agent = v; break;
        case 'Verdict': eventRaw.verdict = v; break;
        case 'Tally': eventRaw.tally = parseTally(v); break;
        case 'P0/P1/P2': {
          const [p0, p1, p2] = v.split('/').map((s) => Number(s.trim()));
          eventRaw.p0_count = p0; eventRaw.p1_count = p1; eventRaw.p2_count = p2;
          break;
        }
      }
    }
    return EventSchema.parse(eventRaw);
  });
}

function parseOutcomeRef(text: string): { kind: 'file' | 'wikilink'; ref: string } {
  const m = text.match(/^\[\[(.+?)\]\]$/);
  if (m) return { kind: 'wikilink', ref: m[1] };
  return { kind: 'file', ref: text.replace(/`/g, '') };
}

function parseTally(text: string): { accept: number; concerns: number; block: number } {
  const acc = Number(text.match(/(\d+)\s+ACCEPT/i)?.[1] ?? 0);
  const con = Number(text.match(/(\d+)\s+CONCERNS?/i)?.[1] ?? 0);
  const blk = Number(text.match(/(\d+)\s+BLOCK/i)?.[1] ?? 0);
  return { accept: acc, concerns: con, block: blk };
}

function parseObservations(children: Root['children']): SessionNote['observations'] {
  const list = findList(children);
  if (!list) return [];
  return list.children.map((item) => {
    const text = nodeToString(item).trim();
    const m = text.match(/^\[(\w+)\]\s+(.+?)(\s+(#[a-z0-9-]+(\s+#[a-z0-9-]+){0,2}))?$/);
    if (!m) throw new ParseError(`Observation malformed: ${text}`, { path: ['observations'] });
    const tags = (m[4] ?? '').split(/\s+/).filter(Boolean).map((t) => t.slice(1));
    return { category: m[1] as any, text: m[2].trim(), tags };
  });
}

function parseRelations(children: Root['children']): SessionNote['relations'] {
  const list = findList(children);
  if (!list) return [];
  return list.children.map((item) => {
    const text = nodeToString(item).trim();
    const m = text.match(/^(\w+)\s+\[\[(.+?)\]\]$/);
    if (!m) throw new ParseError(`Relation malformed: ${text}`, { path: ['relations'] });
    return { verb: m[1] as any, target: m[2] };
  });
}
```

### Parser design decisions baked in

1. Headings are the index — H2 sections are the top-level structure; H3 sub-sections walked separately.
2. Derived sections are skipped, not parsed — Progress Dashboard and Cross-Part Dependency Graph are regenerated by the renderer.
3. Wikilink as `{ ref }` object — preserves the wikilink-vs-plain distinction through the model.
4. Phase is derived from part id — eliminates a drift surface.
5. Schema parse is the final step — bugs surface as Zod issues at a known boundary.
6. `<details>` blocks in Tasks archive: assumes remark's table-finder recurses into HTML; may need to switch to plain H3 + table if remark drops content inside `<details>`.
7. Event types dispatch by Type field bullet — discriminated union narrowing happens at Zod validation.
8. Bullet field map is forgiving — unknown bullets ignored; Zod catches schema gaps.
9. bulletFieldMap matches both `- **Field**: value` and `- Field: value` — accommodates LLM authoring variance.
10. ParseError carries a path array — gives Zod-style locality for error messages.

### Parser edge cases surfaced

1. Pending User Decisions body shape — stubbed to return [] for the common "None — ..." case; real PUD body shape locks when first real use case emerges.
2. Bullet field map vs paragraph body ordering in events — parser assumes bullets-first, paragraphs-after. Renderer enforces this order.
3. `<details>` collapse in Tasks archive — depends on remark's HTML handling. Fallback: drop the collapse, use plain H3 + table.
4. Multi-line cell content in tables — remark uses `<br>` for line breaks; parser may need `<br>` → `\n` mapping for cell content.
5. Frontmatter title quoting — YAML single-quotes around colon-containing titles handled via js-yaml.

## Appendix E: Renderer sketch

The renderer is the inverse of the parser: typed in-memory model → markdown string. Expected size ~150-200 LOC each for plan + session renderers. Uses unified + remark-stringify for emission so the same AST library is used both directions.

```ts
}
```

## Appendix H: Round-trip property test design

```ts
import { sha256 } from 'crypto';
import { readFileSync } from 'fs';
import { parsePlanNote } from './parsers/plan-note';
import { renderPlanNote } from './renderers/plan-note';

test('plan round-trip identity', () => {
  const md = readFileSync('docs/planning/PLAN-001-skills-ecosystem.md', 'utf8');
  const parsed = parsePlanNote(md);
  const rendered = renderPlanNote(parsed);
  expect(sha256(rendered)).toBe(sha256(md));
});

test('session round-trip identity', () => {
  const md = readFileSync('docs/sessions/SESSION-2026-05-19_01-skills-bootstrap-and-plan-001.md', 'utf8');
  const parsed = parseSessionNote(md);
  const rendered = renderSessionNote(parsed);
  expect(sha256(rendered)).toBe(sha256(md));
});
```

These become CI gates. Once parser + renderer pair achieves round-trip for the dogfood fixtures, the mutation API can be built on top with confidence that no incidental change to the markdown occurs from a no-op operation.

For the existing PLAN-001 (which is the current authoring of the original template, not the trimmed one), round-trip parity holds only after PLAN-001 is re-authored to the trimmed template. Strategy: parse current PLAN-001, drop the dropped sections (Workflow Plan / Decision Log / Progress Log / per-part redundancies), consolidate Tasks at top level, render → diff. Iterate until char-identity holds against the new trimmed canonical form.
