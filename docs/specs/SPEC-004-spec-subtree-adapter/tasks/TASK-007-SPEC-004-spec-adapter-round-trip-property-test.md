# TASK-007-SPEC-004: SPEC Adapter Round-Trip Property Test

## Design Context

- DESIGN-001-SPEC-004 SPEC Subtree Adapter Architecture: the round-trip test validates the full decompose-recompose cycle across the SPEC subtree
- DESIGN-003-SPEC-004 Per-File Hash Validation Strategy: the test exercises the per-file hash validation path

## Objective

Implement the round-trip property test for the SPEC subtree adapter that proves zero content drift across the full decompose-recompose cycle. The test reads the fixture SPEC subtree, applies the distribution plan (decompose: SPEC-001 to SPEC-003), then applies the composition plan (recompose: SPEC-003 back to SPEC-001), and verifies per-file SHA-256 identity between the original and recomposed files.

## Scope

**In Scope**:

- Round-trip property test at _shared/composition/tests/spec-subtree-adapter.test.ts
- Per-file SHA-256 comparison (root + all children)
- Programmatic inverse plan generation (swap source/dest, invert all maps)
- Error diagnostics: on failure, report which file drifted and first divergence point

**Out of Scope**:

- Adapter implementation (TASK-001 through TASK-004)
- Fixtures (TASK-006)
- ADR/ANALYSIS/SESSION adapter tests (covered by SPEC-001 and SPEC-002)

## Implementation Notes

The test uses bun:test. It reads fixture files from tests/fixtures/spec-subtree/, constructs the SpecSubtreeAdapter, calls processSubtree() with the distribution plan, then calls processSubtree() with the programmatically-generated inverse plan. The inverse plan is generated by swapping source_path/dest_path, inverting renumber_map (swap keys/values), inverting wikilink_map (swap keys/values), inverting frontmatter_map (swap keys/values), and inverting filename_rewrite_map (swap keys/values). This programmatic generation ensures the test does not depend on hand-crafted inverse plans.
