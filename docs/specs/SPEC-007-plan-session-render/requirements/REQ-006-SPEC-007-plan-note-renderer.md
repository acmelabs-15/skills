# REQ-006-SPEC-007: PlanNote Markdown Renderer

## Requirement Statement

WHEN a typed PlanNote model is provided
THE SYSTEM SHALL render it to canonical markdown via `renderPlanNote(plan: PlanNote): string` at `shared/composition/src/renderers/plan-note.ts` producing sections in canonical order (frontmatter, H1 title, Scope with optional Source, Objectives checkbox list, Progress Dashboard derived table, Cross-Part Dependency Graph derived Mermaid, Parts H3 sections with bullet attrs and DoD and optional decisions table, Tasks Active/Backlog/Archive sub-tables, Pending User Decisions, Editor Mirror IDs, Blockers, Observations, Relations) using unified + remark-stringify + remark-gfm
SO THAT the typed model is deterministically serialized to markdown with derived views (Progress Dashboard, Mermaid graph) regenerated from structural content.

## Pattern

Renderer (Stateless: receives typed model, returns markdown string. Derived views regenerated on every render).

## Priority

P0 -- the renderer is one half of the round-trip identity pair.

## Category

Functional

## Context

ADR-003 D-3 locks deterministic render scripts. The renderer is the inverse of the parser: typed model to markdown. ANALYSIS-002 Appendix E provides the renderer sketch. The renderer regenerates Progress Dashboard (D-7 derived view) and Cross-Part Dependency Graph (D-7 Mermaid as separate render concern) from the parts array on every render, eliminating manual dashboard and Mermaid maintenance.

## Acceptance Criteria

- [ ] GIVEN a valid PlanNote model parsed from the trimmed PLAN-001 fixture
      WHEN renderPlanNote() is called
      THEN the output is a valid markdown string containing all canonical sections in order

- [ ] GIVEN a PlanNote with parts in various substatuses
      WHEN renderPlanNote() generates the Progress Dashboard
      THEN the dashboard table counts match the actual substatus distribution across parts grouped by phase

- [ ] GIVEN a PlanNote model
      WHEN renderPlanNote() is called
      THEN the Cross-Part Dependency Graph section contains a Mermaid code block generated by renderMermaid()

- [ ] GIVEN a part with substatus DONE, outcome, and completing_session
      WHEN renderPlanNote() renders that part's H3 section
      THEN all bullet attrs are present in bold-label colon-value format

- [ ] GIVEN tasks in Active, Backlog, and Archive categories
      WHEN renderPlanNote() renders the Tasks section
      THEN three H3 sub-tables are emitted with correct column schemas per category

- [ ] GIVEN the renderer output
      WHEN inspected
      THEN Observations is the second-to-last H2 section and Relations is the last H2 section

## Implementation Notes

Uses unified + remark-stringify + remark-gfm for emission. Expected size 150-200 LOC. The renderer must configure remark-stringify to preserve formatting compatible with the parser's expectations for round-trip identity. Progress Dashboard is a phase-by-substatus pivot table. Mermaid is delegated to renderMermaid() from REQ-008.
